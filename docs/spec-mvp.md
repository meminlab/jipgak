# 집각 MVP 명세 v0.3 — 2026-11-27

이 문서는 레포 `docs/spec-mvp.md`의 원본입니다. 바꿀 때는 기획이 이슈에 변경안을 올리고, 개발이 PR로 반영합니다.
클라이언트 결정(2026-11-19)을 반영했습니다. v0.3(2026-11-27): 5절에 명세 해석 확정(BANB-64 Q1~Q11)과 `policy_rules` 키를 반영했습니다(BANB-65).
- 지역은 수도권입니다.
- 실거래 원본은 7년 보관하고, DB는 무료 한도의 60% 이하로 유지합니다.
- 면적은 API로 받을 수 있는 것을 모두 자동으로 받습니다.
- 방·화장실 수는 직접 입력합니다.
- 나머지 질문(Q6~Q10)은 추천안대로 갑니다.

## 0. 범위
| 구분 | 포함 |
|---|---|
| MVP | 지도·지역 조회 / 단지 상세(실거래·단지정보·면적) / 스크랩(내 단지 목록) / 내 조건 설정 / 대출 가능액·필요 자금 계산 / 정렬 |
| 다음 단계 | 정책대출(디딤돌·보금자리) / 수도권 밖 지역 / 전월세 / 호가 직접 입력 / 청약홈 주택형 연동 |
| 안 함 | 매물(호가) 자동 수집, 민간 플랫폼 크롤링, 매수 추천 |

## 1. 사용자 시나리오
1. 처음 들어오면 로그인합니다(Supabase Auth, 본인 1계정).
2. 내 조건을 입력합니다. 입력하지 않으면 계산 대신 "조건을 입력하세요"를 보여줍니다.
3. 지도에서 지역을 이동하거나 시·군·구와 동을 선택하면 단지 마커가 나옵니다. 마커에는 최근 거래가가 표시됩니다.
4. 마커를 누르면 단지 상세가 열립니다. 상세에는 평형 탭, 실거래 목록과 차트, 단지정보, 이 단지 기준 필요 자금이 있습니다.
5. ☆ 스크랩을 누르면 단지가 내 단지 목록에 저장됩니다. 평형을 하나 이상 고릅니다(기본은 거래가 가장 많은 평형).
6. 내 단지 목록에서는 평형별로 한 줄씩 비교하고 정렬합니다. 방·화장실 수와 공급면적(자동값이 없을 때)은 여기서 직접 입력합니다.

## 2. 화면 (모바일 우선 PWA, 4화면)
| 화면 | 구성 |
|---|---|
| 지도 | 카카오맵, 지역 선택(시·도 > 시·군·구 > 동), 단지 마커(최근가·평형 요약), 축척별 클러스터, "내 예산 안" 필터 토글 |
| 단지 상세 | 헤더(단지명·주소·N년차·세대수·복도유형·주차) / 평형 탭(전용㎡·공급㎡·평형) / 최근 6개월 최저~최고, 최근 1건, 전고점(날짜)과 대비율 / 실거래 표(7년, 해제 거래 표시) + 월별 차트 / 이 평형 기준 대출 가능액(LTV·DSR 나란히)과 필요 자금 / ☆ |
| 내 단지 목록 | 카드 또는 표: 단지·평형, 필요 자금 구간, 대출 가능액, 연식, 세대수, 공급·전용·평형, 방·화장실, 전고점 대비 % / 정렬: 필요 자금 낮은 순(기본), 대출 가능액, 전고점 대비 하락률, 연식, 세대수 / 행에서 바로 수정(방·화장실·공급면적·메모) |
| 내 조건 | 종잣돈, 연소득(세전), 기존 대출 연간 원리금, 주택 수(무주택/1주택/2주택+), 생애최초 여부, 금리(기본값: 설정값), 만기(30년), 상환방식(원리금균등), 이사비 포함 여부와 금액, 금융권(은행 기본) |
- 모든 계산 결과 옆에 다음 문구를 넣습니다: "참고용 계산이며 실제 대출 한도는 금융기관 심사에 따릅니다. 규제 기준일: YYYY-MM-DD"
- **내 조건 입력 검증 (기획 확정 2026-11-27, BANB-64 Q15)**
  - 금액(종잣돈·연소득·기존 원리금·이사비)은 만원 단위 0 이상 정수만 받습니다. 숫자 키패드를 쓰고, 어기면 저장을 막고 해당 필드 아래에 문구를 띄웁니다. 종잣돈은 필수이고, 연소득은 비우면 DSR "계산 불가"입니다.
  - 금리는 0.00~20.00%, 소수 둘째 자리까지 받습니다. 비우면 설정값(`loan.default_interest_rate`)을 씁니다.

## 3. 데이터 출처와 수집
| 데이터 | API(공공데이터포털) | 수집 방식 |
|---|---|---|
| 실거래 | 국토교통부_아파트 매매 실거래가 상세 자료 | 최초 1회 7년치 적재(수도권 약 80개 코드 × 84개월 ≈ 6,700건 호출). 이후 매일 최근 3개월을 다시 받아 신규 거래와 해제를 반영 |
| 전고점(장기) | 같은 API, 2006-01~7년 이전 구간 | 최초 1회. 평형별 최고가만 남기고 원본은 버림(약 1.3만 건 호출, 개발계정 기준 2일) |
| 단지 목록·기본·상세 | 국토교통부_공동주택 단지 목록제공 서비스, 국토교통부_공동주택 기본 정보제공 서비스 | 매월 동기화 |
| 공급면적 | 국토교통부_건축HUB_건축물대장정보 서비스 › 전유공용면적 조회 | **단지 상세를 처음 열 때 또는 스크랩할 때** 해당 단지만 조회해 평형별 결과만 저장(지연 수집) |
| 좌표 | 카카오 로컬 주소검색(REST, 서버 전용) | 새 단지가 생길 때 1회 |
| 규제·세율 | 없음 → `policy_rules` 설정값 | 기획이 기준일·출처와 함께 갱신 |

**단지 연결 규칙**
- 실거래 `aptSeq`와 K-apt `kaptCode` 사이에 공통 키가 없습니다. 다음 순서로 맞춥니다.
  1. 법정동코드+본번·부번이 같은 단지
  2. 같은 법정동 안에서 단지명 정규화(공백·"아파트"·괄호 제거) 후 일치
  3. 실패하면 `unmatched`로 표시합니다. 단지정보 칸은 "정보 없음"으로 두고 실거래는 정상 표시합니다.

**공급면적 계산 규칙 [추정 규칙 — 개발 착수 때 샘플 단지 5곳을 분양 공고와 대조해 확정]**
- 공급면적 = 전유면적 + 주거공용면적(계단실·복도·승강기홀·현관 등)
- 주차장·관리사무소·기계/전기실·주민공동시설 같은 기타공용은 제외합니다.
- 같은 전용면적(0.01㎡ 단위)끼리 묶어 최빈값을 씁니다. 실거래 `excluUseAr`와는 ±0.5㎡ 이내일 때 같은 평형으로 연결합니다.
- 평형 = 공급면적 ÷ 3.3058로 계산하고, 표시는 반올림 정수 "NN평"으로 합니다.
- 공급면적이 없으면 "전용 NN㎡(전용 NN평)"으로 표시하고, 내 단지 목록에서 직접 입력할 수 있게 합니다. 값의 출처(대장/직접 입력)를 함께 표시합니다.
- 실패할 수 있는 경우: 블록 지번(신도시), 부속지번 여러 개, 대장 미등재. 이때는 빈 값으로 두고 직접 입력을 받습니다.

**방·화장실 수:** 공공 API에 없습니다. 내 단지 목록에서 평형별로 직접 입력하며, 개인 데이터로 저장합니다.

|---|---|
| `complexes` | 단지(aptSeq, kaptCode, 이름, 법정동, 지번, 좌표, 사용승인일, 세대수, 동수, 복도유형, 주차, 시공사, 매칭 상태) |
| `area_types` | 단지×전용면적 평형 타입(전용, 공급, 공급 출처, 전고점 가격·날짜, 최근가·날짜, 6개월 최저·최고). 지도·목록은 이 값만 읽음 |

- 월별 집계는 따로 저장하지 않고 조회할 때 계산합니다(7년 범위).

## 5. 계산 규칙 (값은 모두 `policy_rules`에서 읽음)
명세 해석 확정(기획 2026-11-19, BANB-64 Q1~Q11)을 반영했습니다. 손계산 기준은 QA 확정본 `tc-calc-engine-v1.1`(BANB-64)이고, 엔진은 `src/lib/calc/`에 있습니다.

- **기준가(평형별):** 최근 6개월 실거래 최저~최고 → 필요 자금 "구간"을 만듭니다. 최근 1건도 함께 표시합니다. 6개월 안에 거래가 없으면 최근 1건(날짜 표시)만 씁니다.
- **지역 판정:** 단지 시군구가 규제지역 목록(`region.regulated_sigungu`)에 있는지, 수도권 여부(`sigungu_codes.is_capital_area`)를 봅니다. 조정지역 = 이 규제지역 목록입니다.
- **LTV 기준액** = 가격 × LTV(규제 여부, 주택 수, 생애최초)
  - 무주택: 규제지역 40% / 비규제 70%. 생애최초(무주택만): 수도권 70% / 비수도권 80%.
  - **1주택:** 처분조건부로 보고 무주택과 같은 LTV를 적용합니다. 안내: "기존 주택을 6개월 안에 처분하는 조건입니다."
  - **2주택 이상 + 수도권·규제지역:** 대출 0으로 계산하고 "주담대 불가 지역" 안내를 띄웁니다.
- **가격 구간 한도:** **수도권 전체**에 적용합니다. 15억 이하 6억 / 25억 이하 4억 / 25억 초과 2억.
- **DSR 기준액:** 다음 식을 만족하는 최대 원금 P입니다.
  - (연소득 × DSR한도 − 기존 연간 원리금) ≥ P의 연간 원리금. 여력이 0 이하면 0입니다.
  - 금리는 (입력 금리 + 스트레스 금리 × 반영비율), 만기·상환방식(원리금균등)은 입력값을 씁니다. 금리를 비우면 설정 기본값을 씁니다.
  - 스트레스 금리 반영비율은 **100%**이며 `policy_rules` 값입니다. 안내: "고정·혼합형 금리는 한도가 더 클 수 있습니다."
  - 연소득 0 또는 미입력이면 "계산 불가"로 표시하고 LTV 기준만 씁니다.
- **대출 가능액** = min(LTV 기준액, 가격 구간 한도, DSR 기준액). 화면에는 LTV 기준과 DSR 기준을 나란히 보여주고, 실제로 적용되는 작은 값을 강조합니다.
- **부대비용**
  - 취득세(무주택·1주택): 6억 이하 1% / 6~9억 (가액×2/3억−3)% / 9억 초과 3%. 6~9억 세율은 **비율을 소수 다섯째 자리에서 반올림해 넷째 자리까지** 씁니다(7억 → 1.67%).
  - **1주택 보유자:** 일시적 2주택으로 보고 일반세율을 적용합니다. 조정지역이면 안내: "기존 주택을 기한 안에 처분하지 않으면 8% 중과로 추징됩니다."
  - **2주택 이상 보유자:** 조정지역 12%, 비조정지역 8%입니다. 비조정지역이면 안내: "3주택 이상 보유 시 12%"
  - 지방교육세: 일반세율은 취득세율의 10%, 중과는 0.4%. 농특세: 전용 85㎡ 초과만 0.2%(중과 8% → 0.6%, 12% → 1.0%).
  - **생애최초 감면:** 12억 이하, 한도는 설정값. **취득세 본세에만** 적용합니다. 생애최초는 **무주택일 때만** 체크할 수 있습니다(주택 수를 바꾸면 자동 해제, 엔진도 무시).
  - 중개보수(요율 상한, 부가세 제외): **5천만 미만 0.6%(한도 25만) / 5천만~2억 미만 0.5%(한도 80만)** / 2~9억 미만 0.4% / 9~12억 미만 0.5% / 12~15억 미만 0.6% / 15억 이상 0.7%
  - 법무·등기비(설정값, 기본 가격의 0.2% [추정])
  - 이사비(입력값)
- **필요 자금** = 가격 − 대출 가능액 + 부대비용. 종잣돈과의 차이를 "부족 N / 여유 N"으로 표시합니다.
- **반올림과 표시**
  - 내부 계산은 원 단위입니다. **대출 금액은 만원 미만 절사, 세금·보수는 원 미만 절사**합니다.
  - 화면에서 **필요 자금·부족은 만원 미만 올림, 여유는 만원 미만 내림**합니다.
  - 0원이면 "여유 0원"으로 표시하고, 기준가가 구간이면 최저·최고를 각각 표시합니다.
- **금액 표시:** 억·만원 단위입니다(예: 7억 3,500만).
- **규제 기준일:** 화면 고지 문구의 "규제 기준일"은 적용 중인 `policy_rules` 행의 출처 확인일(`checked_on`) 중 가장 최근 값입니다.

**`policy_rules` 키 (초기값: `supabase/migrations/20261127000000_policy_rules_seed.sql`)**
- 비율은 퍼센트 숫자(`rate_pct: 40` = 40%), 가격·한도는 만원, `*_won`은 원입니다. 구간의 `max_price`는 이하, `below_price`는 미만입니다.
- `region_scope`는 `regulated` / `capital` / `all`이고, 엔진은 규제 → 수도권 → 전체 순서로 가장 구체적인 행을 씁니다. 같은 키에 시행일이 다른 행이 있으면 오늘 유효한 행 중 시행일이 가장 늦은 행을 씁니다.

| 키 | 내용 |
|---|---|
| `region.regulated_sigungu` | 규제지역(= 조정지역) 시군구 코드 목록 |
| `ltv.base` / `ltv.first_time` / `ltv.multi_house` | LTV(무주택·1주택) / 생애최초 LTV / 2주택+ 주담대 불가 여부 |
| `loan.price_cap` | 가격 구간 한도 |
| `dsr.limit` / `dsr.stress_rate` / `dsr.stress_ratio` | DSR 한도(은행·2금융) / 스트레스 금리 / 반영비율 |
| `loan.default_interest_rate` | 내 조건 금리 기본값 |
| `tax.acquisition.general` / `tax.acquisition.multi_owner` | 취득세 일반세율 구간 / 2주택+ 보유자 중과 |
| `tax.local_education` / `tax.rural_special` / `tax.first_time_relief` | 지방교육세 / 농특세 / 생애최초 감면 |
| `fee.brokerage` / `fee.legal_registration` | 중개보수 요율 / 법무·등기비 |

## 6. 예외 케이스
- 거래가 0건인 평형은 목록에서 "거래 없음"으로 표시하고 정렬할 때 맨 뒤로 보냅니다.
- 해제된 거래는 실거래 표에 취소선으로만 보여주고, 기준가·전고점·차트에서는 빼야 합니다.
- 최근 1개월은 신고 기한 때문에 "집계 중"이라고 표시합니다.
- 행정구역이 개편된 경우(예: 화성시 동탄구) 구·신 코드 매핑 테이블로 연결합니다.
- 공공 API 오류나 한도 초과 시 수집은 다음 날 다시 시도하고, 화면은 마지막 수집일을 표시합니다.
- 연소득 0 또는 미입력이면 DSR 기준은 "계산 불가"로 표시하고 LTV 기준만 씁니다.

## 7. 용량 감시
- 매일 수집 잡이 끝나면 `pg_database_size`를 `ops_metrics`에 기록하고, 내 조건 화면 하단에 "DB 사용량 N MB / 500MB"를 표시합니다.
- 주 1회 GitHub Actions(무료)가 DB 용량을 조회합니다.
  - 350MB(70%)를 넘으면 레포에 GitHub 이슈를 자동 생성해 클라이언트에게 메일 알림이 갑니다.
  - 같은 잡이 무료 프로젝트 7일 미사용 일시정지도 막습니다 [추정 — 일시정지 판정 기준은 Supabase 정책 확인 필요].

## 8. 완료 기준 (MVP)
- 수도권 7년 실거래와 2006년~ 전고점이 적재되고, 매일 수집이 3일 연속 오류 없이 돕니다.
- 샘플 1개월 적재 후 실측한 용량으로 7년 용량을 다시 추정했을 때 300MB 이하입니다(넘으면 4절의 줄이는 방법을 적용하고 보고).
- 단지 매칭률(K-apt 연결)과 공급면적 자동 채움률을 측정해 보고합니다. 목표값은 측정 후 정합니다.
- 4화면에서 시나리오 1~6이 동작합니다. 계산값은 QA 테스트 케이스의 손계산과 일치해야 합니다.
- 키는 서버 secrets에만 있고, 브라우저 번들에는 카카오 JS 키와 anon 키만 있습니다.

## 결정 기록
- 2026-11-19 계산 엔진·내 조건 화면은 키 없이 가능해 사용자 흐름 순서(지도→…→예산) 예외로 먼저 머지 허용 (클라이언트 지시: 키 없이 할 수 있는 일부터).
- 2026-11-19 키가 필요한 이슈는 backlog(제목 ⛔키대기)로 둔다. blocked 상태는 담당 에이전트 실행을 바로 깨우므로 쓰지 않는다.
- 2026-11-19 전고점은 2006~ 전체, 평형별 최고가 1행만 저장. 월별 집계는 저장하지 않고 7년 원본에서 계산.
- 2026-11-19 1주택자는 대출(처분조건부)과 취득세(일시적 2주택)에 같은 가정을 적용한다. 계산 결과가 모순되거나 필요 자금이 과장되지 않게 하려는 것 (기획, BANB-64).
